# Whitepaper alignment — version 0.4

Reference: owner-supplied “Airdrop Museum — Whitepaper”, version 1.0, October 2026, four pages. This implementation interprets the museum philosophy as evidence-first presentation and visitor choice. No exhibit is hidden because of a personal risk report or personal rating.

| Whitepaper concept | Implemented behavior | Remaining work |
| --- | --- | --- |

## Design

Porcelain/white surfaces, silver-blue exhibition architecture, navy type, serif editorial headings, restrained borders, exhibit placards and an arch/pedestal composition made with CSS. Logo supplied by owner is retained. Mobile navigation has six destinations: Museum, Gallery, Portfolio, Archive, Visitor Voice, My Pass. Calendar is a tool within Portfolio.

## Scope boundaries

All six bundled projects remain fictional demo content. Personal exhibits, evidence records, statuses and reviews live in the user's browser. Local reviews are never described as public votes. A saved claim stage is not evidence of token ownership. No fabricated trust score, automated phishing verdict, network verification, staking, slash or real reward claim is produced.

The whitepaper proposes Next.js, Node.js and PostgreSQL. The current static modular JavaScript and Cloudflare Worker implementation is retained to avoid an unsupported migration; it is not represented as that proposed production architecture.
